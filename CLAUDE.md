# ReportAI — working notes for engineers and agents

ReportAI turns a field technician's voice note (or text, or photos) into a filled Word/PDF report
in the company's own template, after the sender confirms what was extracted. FastAPI + LangGraph
backend, Nuxt panel. See `PROJECT_ROADMAP.md` for decisions and the current phase.

Two run modes, one codebase:
- **SaaS, multi-tenant** (`SINGLE_TENANT=false`, the default): a super admin creates tenants;
  self-serve signup is coming.
- **Self-host** (`SINGLE_TENANT=true`, the Enterprise plan): one company per server, installed by
  `infra/install/install.sh`, set up through the panel's setup wizard (`docs/install.md`).

## Layout

- `backend/app/` — `api/` (routes: `admin/`, `webhooks/`, auth, setup), `core/` (config, deps,
  scoping, security, logging), `models/`, `repositories/`, `schemas/`, `services/` (`agent/` is the
  LangGraph graph and its nodes, `jobs/` the Postgres job queue), `worker.py` (runs the jobs).
- `backend/alembic/versions/` — migrations. `backend/tests/` — pytest; `tests/eval/` is the golden set.
- `frontend/app/` — Nuxt 4 + Vuetify 4 panel and landing; i18n es/en in `frontend/i18n/locales/{es,en}/`.
- `infra/` — `docker-compose.yml` (dev), `docker-compose.prod.yml` (hosted, behind Traefik),
  `install/` (self-host: compose + Caddy + the `reportai` command).

## Commands

From the repo root (dev stack in Docker, needs `.env` — copy `.env.example`):
- `make up`, `make migrate`, `make test` (pytest without the eval), `make lint` (ruff + mypy),
  `make help` for the rest.
- `make hooks` once per clone: enables `.githooks/pre-commit` (ruff + mypy when `backend/` is
  staged, eslint when `frontend/` is staged).

Backend on the host, from `backend/`:
- `uv run --extra dev ruff check .` and `uv run --extra dev mypy app` (no database needed).
- The rest reads settings from the environment and needs the compose `postgres` up, so first
  `export POSTGRES_HOST=localhost UV_ENV_FILE=../.env` (shell variables win over the file), then:
  - `uv run --extra dev alembic upgrade head && uv run --extra dev alembic check`
  - `uv run --extra dev pytest -m "not eval"` — creates and drops `<POSTGRES_DB>_test`, so two test
    runs against the same Postgres at once break each other.
- `pytest -m eval` (`make eval`) calls the real AI providers and costs money. Never run it casually.
- ruff format is NOT enforced: don't reformat files you are not otherwise changing.

Frontend, from `frontend/` (`node_modules/.bin/<tool>` works where npm is missing; a fresh
worktree needs `node_modules/.bin/nuxi prepare` before eslint can load its config):
- `npm run lint`, `npm run typecheck`, `npm test`

CI (`.github/workflows/ci.yml`) runs all of the above except the eval, plus `npm run build` and the
production image build.

## Invariants

- **Tenant isolation.** Every tenant-scoped route takes the tenant from the authenticated user with
  `require_tenant_id` and loads rows with `get_scoped_or_404` (`backend/app/core/scoping.py`).
  Another tenant's row is a 404, never a 403 (a 403 confirms the id exists). Never take a tenant
  id from the request body or query.
- Every new route with a path id goes into the tenant-isolation test matrix
  (`backend/tests/test_tenant_isolation.py`, added in Fase 4).
- **Self-host must not change.** New feature flags default to off; a `SINGLE_TENANT=true` install
  behaves exactly as before; new columns get neutral defaults so existing rows stay valid.
- **i18n.** Every bot/user-facing backend message goes through `backend/app/services/i18n.py`,
  in both `es` and `en` (`tests/test_i18n.py` checks keys and placeholders). Frontend strings go
  in both locale folders.
- **Migrations.** Files are `YYYYMMDD_NNNN_<slug>.py` with sequential revision ids (`"0021"`
  revises `"0020"`); follow the latest file in `backend/alembic/versions/` exactly. Review
  autogenerated diffs by hand. Data migrations never import app code: inline what they need
  (`0016` imports `app.core.crypto`; that is the exception, not the pattern).
- **Secrets.** Never log Telegram Bot API URLs or tokens (the URL contains the token; httpx is
  held at WARNING for this reason). Never print `.env` values, in code or in a shell.
- **Errors fail loud.** No `try/except` that swallows an exception; catch only what you handle.
- **Shortcuts are labelled.** A deliberate simplification gets a `ponytail:` comment naming its
  ceiling and the upgrade path, e.g. `# ponytail: global lock, per-tenant locks if throughput matters`.
- **Dependencies.** A new dependency (Python or npm) needs the owner's approval first.
- **Commits.** English, imperative, one logical change each, with a conventional prefix and an
  optional scope as in `git log`: `feat:`, `fix(landing):`, `chore(database):`, `ci:`, `docs:`.
